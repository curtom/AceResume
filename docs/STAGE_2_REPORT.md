## 已交付

### 账户与会话

- 邮箱注册、唯一性与 10～72 位“字母 + 数字”密码校验。
- Argon2id 密码哈希；账号不存在与密码错误采用相同对外错误及相同哈希成本。
- BullMQ `email.send` Worker 与 Mailpit 验证邮件；验证令牌 24 小时有效且仅可使用一次。
- 登录、15 分钟 Access Token、7 天 Refresh Token HttpOnly Cookie；每次刷新轮换并阻止旧令牌重放。
- 安全退出与密码重置会撤销数据库会话，旧 Access Token 随即失效。
- 30 分钟一次性密码重置流程；不存在的邮箱使用相同成功响应，避免账号枚举。
- 注册、登录、刷新、忘记/重置密码的 Redis 基础限流。
- NestJS Auth Guard、当前用户上下文、前端内存令牌、401 单次续期和路由守卫。

### 个人资料库

- Drizzle migration 建立 `users`、`user_sessions`、`email_verification_tokens`、`password_reset_tokens`、`profiles` 与 `profile_entries`。
- 基本信息，以及教育、项目、实习/工作、技能四类多条目 CRUD。
- 条目分页、完整列表排序、软删除、版本乐观锁、稳定错误码和服务端所有权过滤。
- 日期区间、URL、空值、条目类型与 JSONB `schemaVersion: 1` 运行时校验。
- 从用户指定条目创建结构化简历输入快照的应用服务接口；资料更新不会反向修改已创建快照。
- 个人资料页面覆盖 loading、empty、error、success、表单校验、分页、编辑、删除与排序状态。

### 契约与接口

- 认证、用户摘要、资料、四类资料内容、分页、排序和快照均由 `packages/contracts` 的 Zod Schema 定义。
- OpenAPI 已包含 AUTH/PROFILE 路径、操作说明、查询参数及关键请求体。
- API 统一使用 `/api/v1`、UTC ISO 8601 时间、统一响应包装、`requestId` 与稳定业务错误码。
- 一键后端启动脚本在启动 API/Worker 前自动执行 migration，避免数据库缺表导致 500。

## 安全与边界结论

- 所有资料 Repository 查询都包含 `user_id`，跨用户读、改、删与快照选择均返回不可枚举的 404。
- Refresh Token、邮箱验证令牌和密码重置令牌只以 SHA-256 哈希入库；Access Token 不写入 localStorage。
- 邮件和日志不记录密码、令牌、完整个人资料或模型上下文。
- 当前只实现单一账户资料库，不提前创建多简历、模板、文件、AI 或管理后台抽象。

## 已知限制（不阻塞阶段 2）

- 当前前端首包约 1.66 MB（gzip 约 514 KB），Vite 给出 chunk size 提示；阶段 3 页面增长时再按真实路由拆包，避免当前过早优化。
- Mailpit 是本地开发邮件捕获服务；生产邮件 Provider 与投递配置不在本阶段范围。
- 资料快照当前作为应用服务输出，阶段 3 创建简历时才会持久化到简历版本数据模型。
- 若本机 `API_PORT=3000` 已被其他程序占用，一键启动脚本会明确停止并要求在 `.env` 同步调整 API 与 Web 地址，不会擅自选择端口。
