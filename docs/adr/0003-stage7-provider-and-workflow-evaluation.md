# ADR 0003：V1.0 不引入 DeepSeek 备用 Provider 与 LangGraph.js

- 状态：已接受
- 日期：2026-09-27
- 影响阶段：阶段 7、阶段 8

## 背景

阶段 7 要求评估 DeepSeek 备用 Provider，并记录 LangGraph.js 的可行性结论。当前 Qwen 已完成真实结构化生成、Embedding、引用确认与写入验证；AI 工作流使用显式 TypeScript 状态机，已经覆盖重试、失败恢复、人工确认和幂等写入。

## 决策

- V1.0 不新增 DeepSeek Provider。继续保留供应商无关的 `ChatModelProvider` / `EmbeddingProvider` 边界，只有在 Qwen 出现明确 SLA、成本、区域可用性或能力缺口后再立项接入。
- V1.0 不引入 LangGraph.js。现有单向受控状态机能够表达来源选择、检索、生成、安全校验、等待确认和正式写入，没有需要图运行时解决的动态分支或长时间检查点问题。
- 模型、提示词和功能开关由后台配置；请求目的地址和运行时密钥仍受部署环境约束，避免后台配置将简历上下文发送到未授权地址。
- 若后续接入备用 Provider，只能实现现有 Provider 接口，并重新执行结构化输出、防捏造、引用、隐私和真实供应商评测。

## 重新评估触发条件

- 主 Provider 在已定义的可用性目标下持续不达标，且重试无法满足业务要求。
- 出现明确的双 Provider 灾备、成本路由或区域合规要求。
- AI 工作流出现多个可恢复分支、跨小时人工等待、持久化检查点或复杂补偿，普通状态机已产生不可接受的维护成本。

## 后果

- V1.0 少维护一套供应商差异和一套工作流运行时，降低密钥、隐私、依赖和故障面。
- 当前没有自动 Provider 故障切换；AI 不可用时返回稳定错误，手动编辑、自动保存、预览和 PDF 导出仍可独立使用。
