# 阶段 7：管理后台与系统完善交付报告

> 状态：开发完成，待项目负责人审阅；未进入阶段 8  
> 日期：2026-09-27  
> 范围：管理后台、角色与二次认证、模板/模型/Prompt 管理、监控审计、分级限流与系统决策

## 已交付

### 管理员安全与隐私边界

- 同一 Vue 应用新增 `/admin` 独立控制台布局；前端路由仅改善体验，后端 `AdminGuard` 对每个管理接口执行真实角色校验。
- 用户状态、模板写入/发布/下架、模型配置和提示词发布均要求当前管理员密码与操作原因；成功和失败都写入只增不改的审计表。
- 管理端用户接口只返回账号摘要，不提供完整简历、原始材料、分块、引用正文或模型上下文查询接口。
- 管理员不能禁用自己的账号；禁用用户会撤销其现有会话。

### P0 管理能力

- 用户：分页、邮箱搜索、状态查看、禁用和恢复。
- 模板：结构化定义列表、草稿创建/编辑、固定样例测试、版本发布和下架；简历详情与 PDF Worker 按绑定版本读取数据库定义，因此历史下架版本仍可渲染。
- 模型：Provider、可信 Base URL、Chat/Embedding 模型、固定向量维度、超时、输出上限、温度、能力和开关；密钥使用 AES-256-GCM 加密且接口只返回 `secretConfigured`。
- 提示词：版本创建、确定性防捏造检查、按用户稳定分桶的灰度启用、全量启用和历史回滚；AI 任务记录并执行所选版本。
- 监控：AI 请求量、成功/失败、平均延迟、接受/忽略、输入/输出 Token 估算，材料/PDF 状态和 BullMQ 队列等待/执行/失败数。
- 审计：管理员、时间、对象、动作、原因、结果、requestId；无修改或删除接口。

### 系统完善

- 认证沿用现有限流；新增 AI 创建、材料下载、PDF 下载和管理接口独立限流，超限日志仅记录身份哈希、scope、计数和阈值。
- 管理接口继续使用全局 requestId、稳定错误码和统一异常过滤；日志、指标和审计不记录正文、密码、密钥或完整模型上下文。
- AI Worker 每个任务读取已发布模型参数与提示词版本；可信目的地址和实际运行时密钥继续由服务端部署环境限定。
- 数据库新增 `model_configs`、`prompt_versions`、`audit_logs` 以及 AI 用量字段，均由 Drizzle migration 变更。
- DeepSeek 与 LangGraph.js 结论记录在 ADR 0003：V1.0 均不引入，保留清晰接入边界和重新评估条件。

## 操作说明

- 系统不会创建默认管理员或默认密码。需要由本地数据库拥有者把一个已经注册并确认归属的账号角色提升为 `admin`，然后重新登录获取新角色 Token。
- `ADMIN_CONFIG_ENCRYPTION_KEY` 与 `AUTH_JWT_SECRET` 必须使用不同的随机值；页面和日志均不会回显模型密钥。
- Base URL 和 Embedding 维度在当前部署中不可在线改变，防止未经授权的数据外发和混用向量空间。

## 已知限制

- Token 用量目前按中文字符近似估算并明确标注，不冒充供应商账单；后续可在 Provider 接口统一返回 usage 后切换为真实值。
- 当前没有敏感用户内容排障入口，因此管理员无法查看正文；若未来确有合规排障需求，应另行设计临时授权、用户知情和更细审计。
- 后台加密保存的模型密钥尚未自动成为 Worker 的运行时密钥；当前真实调用继续使用已配置的 `DASHSCOPE_API_KEY`。如需后台密钥热切换，必须明确授权 Worker 解密后把最小必要简历上下文发送到固定的 Qwen 地址。
